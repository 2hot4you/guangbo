### 五类内页模板

1. 首页：独立 Hero + 三类模型能力与生态 + 四个同级业务段落 + 公司联系。避免每段都套相同三列卡片。
2. 业务总览（`/ai`、`/idc`）：独立 H1/导语 → 分类导航 → 对应生态或部署维度 → 场景 → 选型/咨询。AI 用模型类别和生态分组，IDC 用四服务对照与部署条件。
3. 模型分类（3 页）：H1/简介 → 核心任务/创作方式 → 系列列表 → 场景 → 选型要点 → 相关分类。型号能力的限定词（「按型号」等）须留在可见内容中。
4. 产品方案（7 页）：H1/适用需求 → 产品/服务方式 → 该业务独特的决策维度 → 场景或交付方式 → 相关业务。机柜突出选址与供电/制冷/网络，GPU 突出任务和部署方式，专线用可访问的连接示意，能源用服务项与流程。
5. 公司页：公司正式名称与成立时间 → 业务实践 → 协作方式 → `id="contact"` 联系区。不存在确认过的联系方式时，仍可展示公司介绍，但不编造电话、邮箱、地址或假表单。

以上来自 `docs/官网展示页设计方案.md:35-43`、`docs/官网展示页开发准备清单.md:32-34`；逐页内容源见 `docs/网站各板块介绍页文案.md:99-744`。每页保留独立 H1、简介、实质模块和相关业务链接；骨架阶段至少可见标题、简介与核心业务模块，不能统一写「敬请期待」（`docs/前端框架新对话交接.md:36`）。

### 浅色科技风令牌建议

用户已定白底蓝主色（`docs/官网展示页设计方案.md:12-16`）。以下是待视觉验收的候选值，集中定义为语义 CSS 变量并映射 HeroUI 主题，避免逐组件散落覆写：

| 语义 | 候选值/规则 | 用途 |
| --- | --- | --- |
| 页面底色 | `#FFFFFF` | 主背景 |
| 区块底色 | `#F5F9FF` | 轻分区，不形成大面积蓝紫渐变 |
| 品牌蓝/主动作 | `#2563EB`，文字白色 | 主 CTA、激活状态；正文链接另核对比度 |
| 深色文字 | `#10243E` | 标题与正文主层 |
| 次级文字 | `#475569` | 说明，避免浅灰小字 |
| 线框 | `#DCE6F2` | 卡片边界/分隔 |
| 暖色点缀 | 从 Logo 的橙色取样，低占比使用 | 图形节点/强调，不单靠颜色传达状态 |
| 排版 | 中文系统字体；正文 16px 起、行高约 1.65；标题按视口以 `clamp()` 缩放 | 长中文标题与模型名允许换行 |
| 空间 | 4/8px 基础尺度；容器最大宽约 1200px；手机左右留白 16–20px | 一致节奏与小屏阅读 |
| 卡片 | 12–20px 圆角、1px 轻边框、很轻阴影或无阴影 | 信息清晰优先 |
| 状态 | 明显焦点环；hover/pressed/selected/disabled 各可辨 | 键盘与触控反馈 |

Hero 使用排版、细线结构和 LLM/图像/视频能力示意即可；Logo 保持原比例，小尺寸展示，不放大原始 407×111 PNG。Logo 的彩色节点可作为少量视觉呼应，但主页面仍以白、蓝、浅蓝灰为核心。

### HeroUI v3 适用边界

- 优先用于真正有状态与交互的按钮、菜单/抽屉、表单控件、卡片等；具体组件在实施前查**安装版本对应**的 v3 文档/API。视觉网格、Hero、场景示意、信息层级与响应式布局由语义 HTML + CSS/Tailwind 实现。依据 `docs/前端技术栈与SEO方案.md:13-19`。
- v3 使用 React 19+、Tailwind 4、`@heroui/react` 与 `@heroui/styles`；Tailwind 样式先于 HeroUI 导入；无 v2 的 `HeroUIProvider`。HeroUI skill 说明 v3 的复合组件、CSS 变量主题与 `onPress`；不要用 v2 的平铺属性或旧主题写法。
- 导航项与相关服务入口应保留可抓取的真实 `<a href>`/Next Link 语义。HeroUI 不代替全站内容架构或 SEO；长正文、列表、表格仍按 HTML 语义组织。Client 交互只包裹展开导航等局部区域，核心正文出现在初始 HTML（`docs/前端技术栈与SEO方案.md:7-9,21-27`）。

### 移动导航与响应式

- 建议移动优先：小屏顶部保留 Logo、菜单按钮；菜单为可关闭的展开区/抽屉，展开时有明确标签与状态；「大模型」「IDC」各有总览链接和单独子菜单展开控制，不能只靠 hover。路由变化后关闭菜单，键盘焦点返回合理位置。
- 内容随宽度自然重排：320/375/390 单列，约 768 可双列，1024+ 可三/四列，具体以内容断点调整；切勿在窄屏保留固定宽的模型系列卡片。按钮并排不足时换行/纵排；长英文模型名设置换行策略。
- 页脚在手机按业务组堆叠；咨询动作不被悬浮元素遮挡；全页无横向溢出。表格改摘要卡或限定容器滚动，保留键盘可达的滚动区域。检查 320、375、390、768、1024、1440 CSS px 及关键过渡尺寸（`docs/前端技术栈与SEO方案.md:31-36`）。

### 无障碍最低要求

- 每页一个 H1，标题按层级递进，`header/nav/main/footer`、列表与数据表格语义完整；提供跳转主内容链接，当前导航用 `aria-current="page"`。
- 菜单按钮有可理解名称及 `aria-expanded`/`aria-controls`；子菜单可键盘打开、进入、关闭，Escape/点击外部处理与焦点管理一致。所有实际链接可键盘操作，焦点可见。
- 普通文本目标达到至少 4.5:1 对比度，大字号至少 3:1；按钮/图标与非文本 UI 的关键边界按 3:1 检查。蓝字、次级灰字、橙色点缀都需在实际背景上复核；不能仅凭颜色指示选中或错误。
- 点击/触摸目标以至少 44×44 CSS px 为设计目标；不把关键信息藏在 hover。尊重 `prefers-reduced-motion`；自动视频/滚动效果不用于首期。
- 图片写有意义的 alt；纯装饰图用空 alt。信息图若承载结构（如专线连接示意），旁边给等价文字顺序。Logo 链接可用「光波互联，返回首页」一类可理解名称；不要用图像代替可选择、可朗读的正文。
- 若后续增加真实表单，使用关联 label、错误说明、输入类型/自动填充与明确提交结果；本轮无接收后端时不显示假成功表单。

### 素材使用风险

`manifest.json` 的 `asset_map` 是从源文件到导出文件的映射，不是图片授权或可直接上站清单。其 `group` 分为 `profile`、`product/idc`、`product/madeinchina`、`product/network`、`product/energy`。其中 IDC 素材集中在 doc-04–16，信创在 doc-17–21，专线 doc-22，能源 doc-23–24；doc-01 是主体 Logo。doc-14 的 `asset_map` 为空，doc-15 存在一个提取 warning。仅这些事实不足以判断哪张可用。准备清单统计 5844 个素材、447 张尺寸至少 800×450 的栅格图，但它们可能是整页、背景或带字图（`docs/官网展示页开发准备清单.md:7`）。

选图前逐张实际查看并记录 `doc id → source → 导出文件 → 页面用途`，核对拍摄对象、第三方名称/标识、客户信息、资质证书、使用权和图内文字。合作方机房、项目、荣誉不可暗示为光波互联自有。优先选无第三方可识别标识的机房设备与能源实景，并压缩/裁切成网页尺寸；只复制精选图进入网站资源目录。AI 板块先用文字标识、能力卡和自制结构图；未经确认的品牌 Logo 不作为装饰或合作证明。依据 `docs/官网展示页设计方案.md:51`、`docs/网站各板块介绍页文案.md:748-779`。

## Risks

1. **文案承诺失真**：总文案的内部编辑说明明确不应上站；模型生态不等于已接入目录，控制台、价格和在线生成未交付。不能复制所有按钮到可点击 UI（`docs/网站各板块介绍页文案.md:5,768-779`）。
2. **联系动作失效**：对外电话/邮箱/微信尚缺，原资料地址未确认。`/about#contact` 仅在联系区提供真实内容时可作为有效操作（`docs/官网展示页开发准备清单.md:19`）。
3. **资产归属误导**：IDC/能源/专线材料来自合作方；文案已经去名，图片仍可能带品牌、客户资料或资质，不可直接迁移为主体公司的实景证明。
4. **模板过度统一**：若 14 页只有标题加同一卡片网格，会掩盖模型生态、机房选址、专线拓扑和能源服务流程的不同信息需求。
5. **视觉失真**：Logo 小而横向，若在手机强行拉宽或以低对比浅蓝文字承载正文，会同时损害品牌和可读性。
6. **响应式假通过**：仅模拟单个手机尺寸会漏掉 320px 溢出、平板导航过渡、iOS Safari 的安全区与中文换行。文档要求浏览器和实机情况如实记录（`docs/前端技术栈与SEO方案.md:31-37`）。
