# 光波互联官网前端基础框架设计规格

日期：2026-09-23  
状态：已完成会话设计确认，等待书面规格复核

## 1. 目标

在当前资料仓库中从零建立光波互联中文官网的前端基础框架。首轮交付包含 Next.js App Router 工程、HeroUI v3 接入、统一主题和公开页布局、响应式导航与页脚、使用真实文案的首页、14 个公开页面路由骨架，以及公开页面的基础 SEO 能力。

网站面向了解大模型能力、IDC 与算力、信创与企业数字化、专线网络、绿电能源及公司信息的企业访客。访客应能快速理解业务范围，进入对应介绍页，并在真实联系渠道具备后找到咨询入口。

## 2. 范围

### 2.1 本轮包含

- 使用 pnpm 建立 Next.js App Router、TypeScript、React 19、Tailwind CSS 4、HeroUI v3 工程。
- 锁定经验证相容的稳定依赖并保留 `pnpm-lock.yaml`。
- 本地开发地址固定为 `http://localhost:43187`。
- 建立白底、蓝色主色的浅色科技主题。
- 建立公共根布局、响应式导航、移动菜单和页脚。
- 建立首页及其真实内容区块。
- 建立 14 个公开展示页面的显式路由骨架。
- 为每页提供真实标题、简介和至少一个核心业务模块。
- 提供独立 metadata、canonical、Open Graph/Twitter 摘要、sitemap、robots 和统一 404。
- 配置 HeroUI React MCP，并验证组件列表与组件文档能力。
- 生成并审查 HeroUI React v3 官方参考索引，不覆盖现有规则。
- 完成自动测试、类型检查、lint、生产构建和本地浏览器验收。

### 2.2 本轮不包含

- new-api 接入、模型调用联调或实时可用模型目录。
- 登录、注册、账户、客户控制台、API Key、调用记录、充值或支付。
- 在线聊天、生图、生视频、知识库或智能体工作台。
- CMS、业务数据库、Redux 或大型动画框架。
- 虚构的套餐、库存、价格、SLA、案例、资质、联系方式或模型接入状态。
- 将合作伙伴的机房、网络、能源、资质和案例写成光波互联自有资源。
- 未经逐张核验的原始 PDF/PPT 图片直接上站。

## 3. 事实来源与优先级

面向访客的内容仅使用 `docs/网站各板块介绍页文案.md` 中每页“页面正文开始”至“页面正文结束”之间的文字。内部编辑说明、资料来源备注、报价和开发约定不得进入页面。

路由范围以 `docs/首期页面清单与数量.md` 的 14 个公开展示页面为准。缺失内容及发布限制以 `docs/官网展示页开发准备清单.md` 为准。视觉和页面组织以 `docs/官网展示页设计方案.md` 为准。技术和 SEO 约束以 `docs/前端技术栈与SEO方案.md` 为准。

品牌素材使用 `profile/logo.png`。其他素材通过 `extracted/all-materials/manifest.json` 的 `doc id`、来源路径和 `asset_map` 追溯；只有人工查看、确认内容和归属、记录用途并完成网页优化的图片才能复制到网站资源目录。

## 4. 技术方案

### 4.1 技术栈

- Next.js App Router
- React 19 与 React DOM 19
- TypeScript
- Tailwind CSS 4 与 `@tailwindcss/postcss`
- HeroUI React v3 与 `@heroui/styles`
- pnpm
- Lucide React 用于通用界面图标
- Vitest 与 Testing Library 用于单元和组件测试
- Playwright 用于路由、响应式和浏览器验收

安装前重新查询稳定版本与 peer dependencies。版本必须满足 HeroUI React v3 对 React 19 和 Tailwind CSS 4 的约束，并通过安装、测试和生产构建验证。不得仅依据 `latest` 标签假定所有工具兼容。

### 4.2 渲染边界

页面、布局、内容区块和 SEO 默认使用 Server Components。正文存储在本地类型化数据中，公开页在构建时静态预渲染。

只有确实需要浏览器状态的区域使用 Client Components：

- 桌面下拉导航。
- 手机菜单与分组展开状态。
- HeroUI Drawer、Dropdown 等交互控件。
- 路由变化后的移动菜单关闭与焦点恢复。

根布局和整页不得添加 `use client`。核心标题、简介、业务说明和主要链接必须出现在初始 HTML 中。

本轮保持 Next.js 常规部署能力，不启用全站 `output: "export"`。这为后续账户与控制台的服务端认证和动态能力保留空间。

## 5. 文件与模块边界

实施计划应按以下职责划分文件，具体文件名可在计划阶段细化：

- `src/app/`：App Router 路由、根布局、metadata 文件和 404。
- `src/app/(marketing)/`：14 个公开展示路由。
- `src/components/layout/`：站点导航、手机菜单、页脚和主内容跳转链接。
- `src/components/marketing/`：首页、业务总览、模型分类、产品方案和公司页模板及其可复用区块。
- `src/components/ui/`：对 HeroUI v3 组件的少量项目级组合封装。
- `src/content/`：路由清单、导航结构、页面 metadata 与结构化正文数据。
- `src/lib/`：站点地址、SEO、环境判断和内容校验等纯函数。
- `public/brand/`：经过确认的品牌 Logo。
- `public/images/`：经过来源核验和网页优化的精选图片；首轮没有合格图片时保持为空。
- `tests/`：路由、内容、SEO 和组件测试。
- `e2e/`：浏览器级路由、导航和视口验收。

## 6. 内容模型与数据流

### 6.1 单一事实来源

建立类型化路由清单，至少包含：

- `path`
- `slug` 或路由标识
- `section`
- `navLabel`
- `title`
- `description`
- `canonicalPath`
- `template`
- `relatedPaths`
- 对应正文数据引用

导航、页脚、面包屑、页面 metadata、sitemap 和相关服务链接均从这份清单派生，禁止在多个文件重复维护 14 条路径。

页面正文按可组合区块建模，例如：

- hero
- feature 或 capability items
- model groups
- service comparison
- scenarios
- selection criteria
- delivery process
- related services
- contact section

数据模型保留原文中的限定词，例如“按型号确认”“以平台目录为准”“具体资源以项目确认为准”，避免在卡片化过程中扩大承诺。

### 6.2 数据校验

测试和类型检查必须阻止以下情况进入构建结果：

- 路径重复。
- 路由清单不是正好 14 条公开路径。
- related path 指向不存在的公开页面。
- 页面缺少 title、description、H1 文本或核心内容。
- 访客内容包含“内部编辑说明”“不上站”“敬请期待”等不应发布的标记。
- 当前范围出现 `/login`、`/console`、支付或在线生成入口。

## 8. 首页设计

首页严格按以下顺序组织：

1. 首屏：标题“让大模型走进应用，让创意成为内容”及原文简介。
2. 大模型三类能力：LLM、多模态理解；图像生成与编辑；视频生成与编辑。
3. 模型生态：文字化系列标识和“实际可调用范围以平台目录为准”的限定说明。
4. IDC 与算力：总览及 VPS、裸金属、机柜、GPU 四类入口。
5. 信创与企业数字化。
6. 专线网络。
7. 绿电与清洁能源。
8. 从需求到交付的协作方式。
9. 公司介绍与可用联系入口。

当前不显示“查看可用模型与价格”、控制台、在线生成或无真实目的地的按钮。首屏右侧使用轻量 CSS 图形表达 LLM、图像和视频能力，不伪造产品界面、客户数据或调用状态。

## 9. 内页模板

### 9.1 业务总览

用于 `/ai` 和 `/idc`。两页共享页面层级，但内容表达不同：AI 以能力类别和模型生态为核心，IDC 以四类服务和整体部署条件为核心。

### 9.2 模型分类

用于 LLM、图像和视频页面。结构为标题与简介、主要任务或创作方式、模型系列、应用场景、选型要点和相关模型分类。长系列优先使用分组卡片；确需表格时在手机端转换为摘要卡片或限制在可访问的横向滚动容器内。

### 9.3 产品方案

用于 VPS、裸金属、机柜、GPU、信创、专线和能源页面。共享标题、适用需求、服务方式、场景和相关业务骨架，但保留各业务独特表达：

- 机柜突出地域、供电、制冷、网络、安全和运维。
- GPU 突出任务特征、显存、多卡互联、存储和部署方式。
- 专线使用可访问的站点连接结构，并提供等价文字说明。
- 能源使用服务项目与评估流程，而不是虚构能源产品参数。
- 信创使用分层方案，但不把第三方软件写成自研产品。

### 9.4 公司介绍

用于 `/about`。展示正式公司名称、成立时间、业务实践和协作方式。保留 `id="contact"` 的结构位置，但只有经确认的电话、邮箱、微信或地址才能显示。未具备联系渠道时不显示空卡片、假表单或不可完成的咨询按钮。

## 10. 视觉系统

视觉采用白色主背景、浅蓝灰分区、蓝色主动作和深蓝灰文字。Logo 中的暖色只作少量点缀，不用于大面积渐变。

候选语义令牌：

- 页面背景：`#FFFFFF`
- 分区背景：`#F5F9FF`
- 主动作：`#2563EB`
- 主文字：`#10243E`
- 次级文字：`#475569`
- 轻边框：`#DCE6F2`

最终值通过对比度检查后以 CSS 变量集中定义，并映射 HeroUI 主题。颜色使用 OKLCH 或明确的语义变量；不得在组件中散落无语义的硬编码颜色。

中文使用系统字体栈。正文基础字号不低于 16px，行高约 1.65。标题使用 `clamp()` 按视口平滑调整。内容容器最大宽度约 1200px，手机左右留白 16 至 20px。卡片使用轻边框、适度圆角和极轻阴影或无阴影。

Logo 保持原比例并以小尺寸展示，不放大低分辨率原图。

## 11. HeroUI v3 使用规范

- 使用 `@heroui/react` 和 `@heroui/styles`。
- 全局 CSS 先导入 Tailwind CSS，再导入 HeroUI styles。
- 不添加 HeroUI v2 的 `HeroUIProvider`、`@heroui/theme` 或基础 Framer Motion 依赖。
- 使用 v3 复合组件结构，不套用 v2 平铺属性。
- 交互事件优先使用组件文档规定的 `onPress`。
- 按钮、卡片、下拉菜单、抽屉、面包屑和表单控件在编码前必须读取锁定版本对应的组件文档、anatomy、props 和示例。
- HeroUI 负责可访问的控件与状态，Hero、网格、长正文、结构图和业务版式使用语义化 HTML 与响应式 CSS。

## 12. HeroUI MCP 与参考文档

项目级 `.codex/config.toml` 配置官方 `heroui-react` MCP，命令为 `npx -y @heroui/react-mcp@latest`。由于 Codex 通常在启动时加载 MCP，当前桌面会话可能需要重启才能在工具列表中出现。

验收分两层：

1. 通过 MCP 协议实际启动服务器并调用组件列表与组件文档工具，证明服务器和工具可用。
2. 重启 Codex 后确认 `heroui-react` 出现在可调用 MCP 工具中。若第二项无法在本轮会话完成，交付报告必须明确说明，而不能写成已验证。

运行 `npx heroui-cli@latest agents-md --react --output HEROUI_REFERENCE.md` 前后检查文件变化。官方文档下载到独立输出，先审阅索引、`.heroui-docs/react/` 和 `.gitignore` 副作用。

当前磁盘没有项目 `AGENTS.md`。因此不得用 CLI 直接生成并覆盖项目规则；只建立最小项目规则入口并引用 HeroUI 索引，同时声明会话和 CCG 指令优先。若实施期间发现已有 `AGENTS.md`，必须使用增量补丁追加引用，不得修改 CCG 管理块或覆盖用户规则。

## 13. 导航与交互

### 13.1 桌面导航

- Logo 链接至首页。
- 大模型与 IDC 使用 HeroUI v3 下拉菜单。
- 下拉菜单包含栏目总览和所有子页。
- 信创、专线、能源和关于我们直接导航。
- 当前页面或栏目使用 `aria-current` 和非颜色单一表达的选中状态。

### 13.2 手机导航

- 顶部保留 Logo 和至少 44×44 CSS px 的菜单按钮。
- 使用 HeroUI v3 Drawer。
- 大模型和 IDC 的栏目总览链接与子项展开按钮分离，保证总览页可达。
- 支持键盘操作、Escape 关闭、焦点限制和关闭后的焦点恢复。
- 路由变化后关闭菜单。
- 不依赖 hover 展示任何必要信息。

### 13.3 动效

仅使用短促的状态过渡和小幅悬停反馈。不得使用自动播放大视频、重型粒子背景或持续滚动。尊重 `prefers-reduced-motion`。

## 14. 响应式与无障碍

移动优先实现。目标视口为 320、375、390、768、1024 和 1440 CSS px，并检查关键过渡宽度。

- 320 至 767px 以单列为主。
- 768px 起按内容进入双列。
- 1280px 以上启用完整桌面导航；1024px 保持紧凑 Drawer 导航以避免长中文栏目换行。内容多列布局可按各模块空间独立切换。
- 中文长标题、英文模型名称和按钮允许自然换行。
- 全页不得横向溢出；需要横向滚动的表格只能在自身容器内滚动。
- 手机与桌面呈现同一核心内容，不把关键信息仅放在桌面 hover 状态。

无障碍最低要求：

- 每页一个 H1，标题层级连续。
- 使用 `header`、`nav`、`main`、`section`、`footer`、列表和数据表格语义。
- 提供“跳转到主要内容”链接。
- 所有交互可用键盘完成，焦点样式清晰。
- 普通文本对比度至少 4.5:1，大字号至少 3:1，重要非文本界面边界至少 3:1。
- 触控目标以至少 44×44 CSS px 为设计目标。
- 信息图片有等价文字；装饰图片使用空 alt。
- Logo 链接有可理解的名称。

## 15. SEO 与索引控制

每页输出唯一中文 title、description、canonical、Open Graph/Twitter 标题和描述。页面正文使用可抓取链接和合理内部链接。

站点 origin 从环境变量读取：

- 本地未配置正式 origin 时使用 `http://localhost:43187` 进行预览与测试。
- 未配置真实 origin 的构建结果禁止索引。
- 只有设置真实 origin 且处于生产环境时，robots 才允许公开页面索引。
- 正式发布前必须检查 canonical、sitemap 和 robots，不能发布 localhost 或示例域名。

`sitemap.xml` 只包含本规格的 14 个公开路由。404、未来账户和控制台页面不进入 sitemap。未来账户和控制台页面应 noindex，但权限控制必须依赖认证而不是 robots。

本轮不编造 Open Graph 图片。确认并制作分享图前，只输出真实文字 metadata。

## 16. 异常与边界处理

- 未命中的路由进入统一 404。
- 内容清单路径错误、重复路径、缺 metadata 或 related path 无效时，测试或构建失败。
- 未确认联系方式时隐藏无法完成的咨询动作，不展示占位电话、邮箱、地址、二维码或假表单。
- 未确认正式域名时保持 noindex。
- 43187 端口被占用时报告占用信息并停止启动；不结束其他进程，不自动选择其他端口。
- HeroUI MCP 未在当前 Codex 会话暴露时，区分“配置完成”“协议调用验证完成”和“桌面重启后工具可见”三个状态。
- 图片不存在、未经核验或无法明确来源时不使用，以纯 CSS 结构图和文字内容替代。

## 17. 测试策略

实施遵循测试驱动开发。每项行为先写失败测试并确认失败原因，再写最小实现使其通过。

### 17.1 单元测试

- 路由清单正好包含 14 条路径且路径唯一。
- 导航、sitemap 与 canonical 使用同一清单。
- related paths 均指向有效路由。
- 每页具备 title、description、主标题和核心模块。
- 内容中不存在内部说明和越界入口。
- 站点 origin 和 robots 的开发、预览、生产行为正确。

### 17.2 组件测试

- 桌面导航包含栏目总览与子页。
- 手机菜单可以打开、展开分组、关闭并恢复焦点。
- 当前路由状态可被辅助技术识别。
