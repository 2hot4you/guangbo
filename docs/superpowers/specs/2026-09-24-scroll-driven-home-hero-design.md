# 首页五业务滚动 Hero 与内页首屏统一设计

日期：2026-09-24  
状态：待用户复核

## 目标

将首页现有单一 Hero 升级为一个由自然页面滚动驱动的五状态开场，依次展示大模型、算力、信创、专线网络和清洁能源。五个状态只承担业务概览和视觉识别，不替代首页下方已经展开的完整业务内容。

同时修复站内切页后停在约 `81px`、仍可继续向上滚动的问题，并让 IDC、信创、专线、绿电和关于我们五个一级内页统一使用浅色 Hero。原本用于 Hero 的深色或荧光强调色移动到第一正文栏目，以保留页面节奏。

## 已确认的体验

- 用户使用普通纵向滚动，不拦截滚轮，也不模拟分页滚动。
- Hero 舞台在 Header 下方保持固定，滚动进度依次激活五个业务状态。
- 第五个状态完成后，固定舞台释放，继续进入当前首页的完整业务模块。
- 桌面和移动端都使用相同的五状态顺序；移动端缩短每段滚动距离，并压缩字号和图形尺寸。
- 首页下方的大模型、模型生态、IDC、信创、专线、绿电、交付和公司介绍等现有模块全部保留。

## 信息结构

滚动 Hero 是一个内容模块，内部包含五个状态：

1. `01 / AI`：大模型与 AIGC。突出语言理解、图像生成和视频生成。
2. `02 / COMPUTE`：IDC 与算力。突出 Compute、Storage、Network、Power、Cooling。
3. `03 / XINCHUANG`：信创与企业数字化。突出硬件、系统、应用和数据之间的分层关系。
4. `04 / LINK`：全国专线租赁。突出站点、接入、骨干传输和目标业务之间的连接路径。
5. `05 / ENERGY`：绿电与清洁能源。突出负荷、绿电、储能和能源管理之间的流转。

每个状态包含：编号、英文业务名、中文标题、一段简短说明、一个主要入口，以及一个独立圆形动态图形。内容从现有首页与一级页面文案中提炼，不新增价格、SLA、库存、客户、资质或资源承诺。

## 滚动与状态模型

### 页面结构

Hero 外层提供约五段视口高度的滚动轨道，内部舞台使用 `position: sticky` 固定在 Header 下方。五个不可见的进度区间将自然滚动位置映射为当前业务索引。

不调用 `preventDefault`，不监听并接管滚轮，不使用整页滚动插件。用户可以随时反向滚动，状态随页面位置反向切换。

### 状态计算

使用浏览器原生 `IntersectionObserver` 观察五个进度标记，并以最接近舞台中心的标记作为当前状态。这样避免高频 JavaScript `scroll` 计算，也不需要第三方动画依赖。

进度导航的 `01–05` 可以点击或用键盘激活。激活后滚动到对应进度标记，不直接伪造组件状态，确保 URL 历史、滚动位置和当前视觉一致。

### SSR 与无脚本回退

服务端输出五个状态的全部标题、说明和链接，维持可抓取正文。客户端只负责根据进度切换当前状态。无 JavaScript 时五个状态按自然文档顺序显示，不能只剩第一屏。

页面保持一个 H1：第一状态承载首页 H1，其余状态使用 H2。进度导航使用列表和明确的可访问名称。

## 五种视觉布局

所有状态共用黑、白、浅灰和荧光黄绿色调，但不共用完全相同的排版。

### AI

文字在左、模型轨道在右。圆形轨道包含 LLM、IMAGE、VIDEO 三个节点；外环缓慢旋转，节点轻微漂浮，中心做呼吸变化。

### COMPUTE

基础设施图在左、文字在右，延续 IDC 内页的反向布局。图形包含 Compute、Storage、Network、Power、Cooling 五层节点和双向轨道。

### XINCHUANG

标题偏右，圆形系统图偏左下。四个层级节点沿圆环分布，并以细线连接中心的系统核心，强调层级协作而非产品卡片。

### LINK

标题偏左上，圆形路径图横向拉伸为线路轨道。节点表示业务站点、接入、传输和目标站点，信号点沿路径移动。

### ENERGY

深色图形区域与浅色文字区域错位叠放，中心为能源核心，周围分布负荷、绿电、储能和管理节点。荧光色仅用于能量流和当前节点。

## 动效规则

- 只让当前状态的轨道、节点和核心持续运动；非当前状态暂停动画，避免后台消耗。
- 状态切换使用短距离位移、透明度和比例变化，不使用大幅视差或高速旋转。
- 连续动画优先使用 `transform` 和 `opacity`，避免引发布局重排。
- 当前状态变化不自动抢夺键盘焦点；只有用户激活进度导航时才保持交互焦点。
- `prefers-reduced-motion: reduce` 下停止轨道旋转、节点漂浮、核心呼吸和过渡动画。内容仍随滚动区间即时切换。

## 响应式规则

- 桌面舞台高度约为可视区域减去 Header，高度不会小于主要内容的可读范围。
- 移动端保持文字在图形之前的 DOM 顺序，每个状态的滚动区间更短，图形最大宽度受视口限制。
- 五个进度标记在桌面靠侧边排列，在移动端置于底部横向排列。
- 360、768、1280 和 1440 CSS px 下不得产生水平滚动或裁掉可读节点。

## 内页首屏色调

以下一级页面的 Hero 统一为浅色：

- `/idc`：原深色 Hero 改浅色；第一正文栏目“服务矩阵”改深色。
- `/madeinchina`：原深色 Hero 改浅色；第一正文栏目“需求诊断”改深色。
- `/network`：原深色 Hero 改浅色；第一正文栏目“连接产品类型”改深色。
- `/energy`：原荧光 Hero 改浅色；第一正文栏目“企业用能输入资料”改荧光色。
- `/about`：已经是浅色 Hero，第一正文栏目已经为深色，保持现状。

Hero 内部图形、边框、标签和说明文字需要切换为适合浅色背景的对比度，不保留依赖白色文字的局部样式。Header 始终保持当前浅色状态。

## 切页归零修复

已复现：从页面中段点击主导航切页后，最终 `window.scrollY` 停在约 `81px`。根因是全局平滑滚动与路由变化后聚焦 `#main-content` 共同触发滚动，焦点把主内容顶部对齐到粘性 Header 下方。

修复策略：

- 路由变化后以 `preventScroll` 聚焦主内容，保留无障碍上下文切换。
- 页面导航使用即时滚动归零，不继承全局平滑滚动。
- 平滑滚动仅用于用户主动点击 Hero 进度导航，并在减少动态效果时退化为即时滚动。

## 组件边界

- `HomeHeroStory`：客户端交互壳，负责当前索引、观察进度标记和进度导航。
- `HomeHeroSlide`：渲染单个业务状态的语义内容和布局变体。
- `HomeHeroVisual`：渲染五种圆形业务图形；只接收业务变体与当前状态。
- `RouteTransitionFocus`：负责路由变化后的主内容聚焦与滚动归零，从移动导航中移出这项全站职责。
- 现有 `HomePage` 继续负责首页下方完整模块，不将详细模块并入滚动 Hero。

## 测试与验收

### 组件测试

- 服务端输出五个业务状态的标题、说明和入口。
- 首页只有一个 H1，其余状态标题层级正确。
- 五个进度入口具有明确名称和目标。
- 内页 Hero 色调与第一正文栏目色调符合映射。

### 浏览器测试

- 从页面中段通过桌面和移动导航切换后，最终 `scrollY` 为 `0`，并且 `#main-content` 获得焦点。
- 滚动经过五个区间时，活动状态严格按 `01–05` 顺序变化；反向滚动顺序相反。
- 点击进度入口能到达对应状态。
- 第五状态后正常进入现有首页正文，正文模块数量和链接不减少。
- 正常模式下只有当前状态的连续动画处于运行状态；减少动态效果下全部连续动画停止。
- 360、768、1280、1440 宽度无横向溢出，Header 不因内页首屏色调变化而出现深色状态。

## 非目标

- 不删除、合并或缩短首页下方现有内容。
- 不增加自动轮播、定时切换、滚轮劫持或第三方滚动库。
- 不修改一级页面之后的详情页布局。
- 不新增图片资产、联系方式、价格或业务承诺。
