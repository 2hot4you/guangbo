# H200 与 RTX 5090 裸金属资源设计

## 意图

将用户提供的 H200 集群节点和 8 卡 RTX 5090 裸金属节点作为可独立比较的商品加入官网，让访客在首页快速识别核心配置和价格，并在 `/idc/bare-metal` 查看完整参数、资源规模和交付条件。

## 目标与非目标

- 首页和裸金属页都展示 DeepBlue Server、H200 节点、RTX 5090 节点三张独立卡片。
- 两个页面复用同一份 `bareMetalResources` 数据，避免配置和价格出现双份维护。
- 详情页呈现完整参数；首页仅呈现摘要、四项核心配置、价格与详情入口。
- 新资源没有用户授权的联系方式，不复制 DeepBlue 的电话，也不显示空“咨询”标签。
- 不新增购买、下单、库存 API、筛选器、轮播或图片。

## 关键口径

- 用户写了“8×4090”，同时写明“8×32G”和“128台5090”。由于 RTX 4090 标准显存为 24GB、RTX 5090 为 32GB，本次按 `8 × RTX 5090 32GB` 展示。
- H200 图片中的 `DDR5-5600 ECC RDIMM` 按内存条标称规格保留，并增加“实际运行速率以平台配置为准”，避免把标称速率解释为整机固定运行速率。
- “闭口：⑤年”转成面向访客的“五年合作周期”，不公开不清晰的内部术语。
- H200 的 17 万元为每台每月参考价并标注可议价；RTX 5090 两档价格均使用“最低”口径。

## 方案比较

### 方案一：扩展统一资源目录并复用现有卡片（采用）

在 `bare-metal.ts` 增加两个 `ResourceCard`，详情页继续读取整个数组，首页改为遍历同一数组。必要的空联系人和单项布局由现有组件小幅增强。优点是配置只有一个事实来源、改动集中、SSR 与可访问性模式保持一致。

### 方案二：为 H200 和 RTX 5090 新建专用组件

可以做更定制的视觉层级，但会复制卡片结构、增加维护成本，且三种商品的比较方式不一致，不符合当前资源目录模式。

### 方案三：首页维护独立精选数据

可精确控制摘要字段，但会复制型号、价格和配置，后续极易与详情页不一致。本次不采用。

## 页面结构

- `/idc/bare-metal`：每个资源继续使用具名 `article`；完整规格、价格、适用任务和限定条件均限定在对应卡片内。
- 首页 IDC 区域：服务列表之后按目录顺序纵向展示三张深色资源卡；每张保留资源名称、类别、摘要、四项核心规格、价格和详情链接。
- DeepBlue 既有内容和电话保持原样；新卡的联系人数组为空，组件按条件隐藏咨询行。

## 响应式与可访问性

- 卡片保持纵向堆叠，不在首页狭窄右栏内强行并排。
- 价格、长型号、网络描述允许换行；360、768、1280、1440px 不应横向溢出或内部裁切。
- 每张卡维持唯一标题 ID 和具名 `article`；首页详情链接名称包含商品名。
- 单独的 CTA 或 notice 在多列断点占满可用行，避免空联系人导致错位。

## 交付约束

- 先写并观察失败测试，再实现数据与渲染。
- 公共内容保持服务端渲染，不引入客户端状态或新依赖。
- 完整验证后从精确提交生成发布包，以完整提交 SHA 构建不可变镜像；生产继续仅监听 `127.0.0.1:43187` 并保留旧镜像与 Compose 备份。
